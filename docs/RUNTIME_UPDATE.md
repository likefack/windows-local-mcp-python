# DEVから運用版への更新

`update-localmcp.bat` は、手元の配布物・開発フォルダーの内容を、設定済みの Program Files 運用版へ反映する入口です。日付やファイル一覧を毎回手書きする必要はありません。GitHubからの取得や `git pull` は行いません。未コミットの編集と未追跡のPythonソースも更新対象です。

## 操作

1. 編集内容と必要な機能テストを確認します。
2. LocalMCP の起動ウィンドウと承認画面を閉じます。直接stdio接続を使っている場合は、その接続も停止します。
3. **通常ユーザーで `update-localmcp.bat` を実行**し、表示された更新元・更新先を確認します。
4. 準備検査に成功するとWindowsのUAC確認が表示されます。「はい」で運用版への配備を開始します。
5. 更新後は通常ユーザーの権限でLocalMCPを起動し、Tunnelの接続準備を確認します。ツール定義が変わった場合は、案内に従ってChatGPT側の「更新する」も押します。

更新中は別のLocalMCP起動・設定変更を行わず、更新ウィンドウを閉じないでください。プロセスを強制終了する機能はありません。対象が起動中、所属不明、承認待ち、処理中、改変検出・復旧待ちの場合は中止します。Approved Host のサービス本体は起動したままで構いません。

```powershell
# 配備せず、対象と停止状態だけを読み取り確認
.\update-localmcp.bat -Check

# 稼働中でも準備と隔離した起動テストだけを行う。UAC・入替・再起動なし
.\update-localmcp.bat -PrepareOnly

# 既定以外の登録済み設定を選択
.\update-localmcp.bat -Config "C:\path\to\config.toml"

# 検証・配備まで行い、通常起動は後で手動実行
.\update-localmcp.bat -NoRestart
```

バッチ終了時は結果を表示してキー入力を待ちます。非対話実行では `WLMCP_NO_PAUSE=1` を指定できます。通常起動の子へはこの値を引き継ぎません。

## 対象と更新手順

この初版は、既存のApproved Host運用版・監視サービス・有効なTunnelが設定済みで、1つの設定から運用版を使う構成を対象にします。別の設定で同じ運用版を共有する登録がある場合は中止します。新規導入、別ユーザーの管理者資格情報による昇格、依存関係が壊れた運用版の修復、依存パッケージの一括最新版化は対象外です。

- active configとTunnel stateから更新先を解決します。特定ユーザー名、Python版、日付をコードに固定しません。運用版はProgram Filesの直下にあるディレクトリに限定します。
- `.dev-tmp/runtime-updates/<日時と識別子>/source` に入力を固定します。対象はルートの配布用PowerShell／バッチ、`pyproject.toml`・`README.md`・設定例、製品Pythonソース、更新補助スクリプトです。実設定、資格情報、`.git`、`.venv`、開発用一時出力は含めません。リンクを拒否し、コピー前後の一覧とSHA-256を照合します。
- 既存の依存バージョンを制約として記録します。既存環境の `pip check`、現在版と候補版のMCP初期化・全ツール一覧・日本語ファイル読み戻しを検査します。候補は一時的な設定・作業領域を使い、本番データを操作しません。起動テストは60秒で打ち切ります。
- UAC後、固定した入力を別の保護ディレクトリへコピー・再検証します。既存installerの非 `-Replace` 経路で別の運用環境を作成します。依存取得・ビルドにはネットワーク接続が必要になる場合があります。
- 通常ユーザーの親プロセスが候補の変更不能性、MCP起動と読み戻し、ツール定義の一致を検査します。合格までは旧版へ触れません。
- 対象プロセス、未完了操作、復旧状態を再確認して専用サービスを停止し、旧版を保護されたバックアップへ移動、新版を従来のパスへ移動します。ACLを緩めたり、旧版を削除したりしません。
- サービスを再開し、通常ユーザーで変更不能性・MCP読み戻し・認証付きauthority事前確認を行います。Tunnel stateが準備時から変わっていない場合だけ `server_script_sha256` を更新します。他の設定値、profile、資格情報は維持します。
- 検査失敗時は旧版への復元を試みます。新しい処理・復旧状態・予期しないプロセスが現れた場合は強行せず、`recovery_required` と記録します。接続設定を旧値へ戻すのは、旧版への復元と旧launcherのハッシュ一致を確認できた場合だけです。

既存のTunnel起動用mutexを保持し、切替直前にもプロセスを検査します。直接の `run-server.ps1` 起動は同mutexを使用しないため、更新中に別端末から直接起動しないことが運用上の前提です。

## 記録と復旧

一時出力には固定したソース、ファイルごとのハッシュ、依存制約、更新計画、`installation.log`、`status.json` を残します。ログへRuntime API Keyを出力しません。構築元・旧版・失敗した新版はProgram Files内の `WindowsLocalMCP.source-*`／`.before-*`／`.failed-*` などに残し、自動削除しません。

`installed` は通常ユーザーでの事前確認まで成功した状態です。実際のApproved Hostコマンド実行、異常終了からの復旧、ChatGPTでの添付転送の実証を意味しません。Tunnel再起動失敗は「更新済み・接続未確認」と報告し、`run-localmcp.bat` からの診断を案内します。

停電、更新ウィンドウの強制終了、並行する手動変更では、runtimeと接続設定の復元を完了できない場合があります。`status.json` とログを確認し、保護された旧版を保持したまま復旧してください。接続設定の対応が不明な場合は `configure-localmcp.bat` のApproved Host運用版設定から再検証します。改変検出や復旧待ちのmarkerを削除して更新を通してはいけません。

## 以前の更新操作との違い

開発用構成では `.venv` へのeditable installと開発用 `run-server.ps1` を使うため、新しく起動するMCPは編集したソースを直接読み込みます。現在のApproved Host構成はProgram Filesへ固定したコピーを使うため、編集を配備する手順が追加されます。このバッチはその手順をまとめるものです。

ChatGPT側の「更新する」は、公開されるツール情報の再取得です。PC内のプログラムをインストールする機能ではありません。[公式手順](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata)も、サーバー更新・再起動後に接続のRefreshを行う順序です。
