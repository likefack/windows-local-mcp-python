# Live Activity の変更表示と operation ID による取得・取り消し

更新日: 2026-10-06

## 表示する内容

局所的な変更操作は、完了が確認された後に、保存済みの変更前後のチェックポイントから
実変更の完全なテキスト差分を表示する。要求された置換文字列や現在の作業ファイルから
変更内容を推測しない。通常の差分プレビューの `max_diff_bytes` を超える部分も表示する。
操作の既存の受付上限は維持する。たとえば `write_file` の生成差分が上限を超える場合は
従来どおり書き込み前に拒否する。ここでの完全表示は、正常に確定した操作の差分を
画面側で追加の文字数・行数上限により切り捨てないことを意味する。

| 操作 | Live Activity の表示 |
| --- | --- |
| `write_file`、`text_file_apply`、`move_file`、`copy_file`、`delete_file`、`make_directory`、`artifact_import_file`、単一ファイルのアップロード確定、`zip_entry_extract` | 対象・件数・時間と完全なテキスト差分。バイナリやフォルダーは変更概要 |
| `workspace_apply`、`workspace_batch`、`workspace_replace`、`workspace_plan_apply`、`structured_file_apply`、`zip_extract_many`、コマンド実行、Undo／rollback | 操作全体で一つの項目とし、対象・変更件数・概要・時間だけ。本文は `operation_changes` で取得 |
| 読み取り・転送 | 対象、取得量など記録済みの概要。転送の内部チャンクを独立した表示行にしない |

高水準操作は、結果が1ファイルだけでも概要表示とする。計画だけの操作は実変更と
区別する。変更がなければ「変更なし」と表示する。成功したように見える記録でも復旧が
必要な状態なら成功差分を表示しない。記録が期限切れ・欠落・不正の場合は読み出せない旨を示す。

実行中は既定で約5秒ごとに経過時間を更新する。終了後の `duration_ms` は所要時間として
表示し、欠損時に推測値で埋めない。転送全体の経過時間とアップロード確定処理の時間は
区別する。承認待ち時間は実行中の処理時間として扱わない。内部処理段階の詳細は
`audit_get` の時間診断で確認する。
構造化ファイル編集は、文書・表・画像の変換に入る前に操作を登録し、変換から確定・
検証まで同じ operation ID で追跡する。変換中の失敗も同じ操作の失敗として記録する。

## 分割転送の終了状態

転送開始APIの成功は、転送全体の終了を意味しない。Live Activityは転送に結び付いた
保存済み状態を読み取り、`cancelled`／`expired`／`failed` を終了として扱う。
受付APIの成功後、次の要求が来ていない転送は `Waiting` として「データ待ち」または
「取得要求待ち」を一度だけ表示する。アップロードの受信バイト数がそろった後も
確定要求が来るまでは「保存確定待ち」とし、`committed` または対応する確定操作の成功を
確認して完了を表示する。待機中は経過時間を更新せず、受信・取得量や状態が変わった時だけ表示する。
保存処理など監査上の操作が実際に実行中なら `Running` として経過時間を表示する。
待機表示は表示履歴の上限を越えても追跡し、後の進捗・期限切れ・キャンセルを見落とさない。
起動前から終了していた転送は再表示せず、
監視中に終了した転送は一度だけ表示し、約5秒ごとの経過時間表示から外す。

期限は保存済み `expires_at` を優先し、旧記録は作成時刻と転送専用TTLから求める。
表示中に期限を過ぎた `preparing`／`open` は表示上のみ期限切れとし、転送記録・監査を更新しない。
記録を取得・検証できなければ「Unknown／転送状態を確認できません」とし、実行中や成功を推測しない。
一時的な読取失敗後も再確認できる。読取は転送単位ロック内でサイズを制限し、
リンク・操作IDや方向の不一致を拒否する。本文や任意のエラー内容は表示へ取り込まない。

## 全変更の取得

表示行末の `[op:<完全なoperation ID>]` を使う。

1. `operation_changes(operation_id, offset=0, limit=50)` で変更対象一覧を取得する。
   `next_offset` があれば次の `offset` に渡し、`eof=true` まで取得する。
2. 対象ごとに `operation_changes(operation_id, path="相対パス", view="diff")` で差分を
   取得する。`next_offset` は次の `content_offset` に渡す。本文ページの位置と
   `max_bytes` はバイト単位であり、ファイル一覧の位置とは異なる。
3. `view="before"`／`view="after"` では、保存済みの変更前／後の実バイト列を
   base64 で取得できる。バイナリもこの方法で完全な内容を取得できる。

各本文ページの `encoding` に従って復号し、順にバイト列として結合する。
差分も多バイト文字の途中で区切られたページは base64 を返す。`sha256` は全内容、
`chunk_sha256` は当該ページの照合用。`next_offset=null` と `eof=true` が終端を示す。
バイナリの `view="diff"` は概要であり、`diff_content_complete=false` を返す。
空ファイルの作成・削除、末尾改行の有無、CRLF、フォルダーの作成・削除も区別する。
一覧の `limit` は1〜200件、本文の `max_bytes` は1バイト〜4 MiBで指定し、実際のページ量は
設定済み `max_transfer_chunk_bytes` 以下に制限する。

`availability` と `complete` を確認する。作成前や削除後の存在しない側、フォルダーの
本文は `not_applicable`。保存期限切れなどで記録が失われている場合は `unavailable` とし、
現在のファイルを過去の内容の代わりに返さない。`complete` は差分の生成元が揃っている
ことを表し、一回の応答に全ページが含まれる意味ではない。
`completeness_scope="recorded_checkpoint_pair"` の範囲であり、操作が成功したという意味でも
ない。併記する `status` と `rollback_state` から失敗・自動復旧・復旧待ちを区別する。

チェックポイントの範囲・操作との対応・許可パスを検証し、返すバイト列を保存済みの
ハッシュと照合する。新規操作は監査に記録した変更前後のマニフェストのハッシュも
照合する。旧記録にこの結合がなければ `manifest_binding="unrecorded"` と明示する。
一覧の内容ハッシュはマニフェスト由来であり、本文を取得するまでは
`content_integrity="not_read"` とする。

`activity_get` の `unified_diff` は従来どおり上限付きのプレビュー。
`operation_report` と `activity_get` は `operation_changes` の呼び出し情報も返す。
本文を巨大な監査項目に複製せず、取得した操作・対象・範囲を監査する。
保存期間と容量制限は既存設定に従い、永久保存を保証しない。
本文ページは取得のたびに対象側の全内容を検証し、差分ページは再生成するため、
大容量ファイルを小さなページで繰り返し取得すると処理量が増える。
画面の完全差分は、途中で検証に失敗した内容を表示しないよう、読み出し完了後に
まとめて出力する。大きな差分では表示量に応じたメモリと出力時間が必要になる。

## operation ID から変更を戻す

- **その操作の変更だけを取り消す**: `request_selective_undo(operation_id)`。
  独立した後続のテキスト変更を保ち、重複・曖昧な変更や変更済みバイナリは競合として停止する。
- **その操作の完了時点へ戻す**: `request_workspace_rollback(operation_id)`。
  対象操作の保存範囲を完了時点へ復元する。対象操作自体を取り消す意味ではない。

どちらもローカル承認画面での承認が必要。`operation_report.rollback` に呼び出し情報と
利用可能性を返す。承認前には復元せず、承認対象の状態と実行時の状態を再検証する。
チェックポイントの通常ファイルと記録したフォルダーが対象であり、`.git`、ACL、
デバイス状態、ネットワーク通信、外部サービスなどの作用は戻せない。

## 表示と安全性

差分本文はローカル承認画面に表示し、低レベル Activity Monitor の永続ログには
複製しない。概要には従来の伏せ字・長さ制限を維持する。差分本文は内容を省略したり
伏せ字にしたりせず、端末制御・双方向制御・不正文字を可視表現に変換し、各行に差分の
接頭辞を付ける。これは画面上の安全な表現であり、実バイト列は詳細取得で確認する。
許可されたファイルに記載された内容は画面に現れるため、画面共有時も本文として扱う。

起動時の完了履歴は再生せず、同じ差分は繰り返し表示しない。承認入力中は差分を
消費せず、再開後に表示する。読み取り本文、生の要求・結果、標準出力・標準エラー、
認証情報、要求ハッシュを一般の概要表示へ追加しない。
表示は観測専用であり、承認・経路選択・競合検知・復旧の根拠には使わない。
